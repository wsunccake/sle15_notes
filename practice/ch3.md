# ch3. 練習題 — 系統觀測與排查

依 `content/ch3.md` 整理的實作與問答練習。目標：能辨識行程與資源握持；盤點 CPU／記憶體／磁碟／網卡；用即時監控抓住當下尖峰；用統計工具驗證是否持續；並依分層步驟排查網路連線問題。

**建議環境**

- SLES 15（或相容 Linux）任一台可登入的系統
- 部分指令（`iotop`、`iftop`、`nethogs`、`vnstat`、`sysstat`、`tcpdump`、`nmap`）可能需另外安裝
- `kill`、`renice`、防火牆、封包擷取、埠掃描僅在**自己管理或已授權**的實驗機操作
- 部分硬體／監控指令需要 `root` 或 `sudo`

**安裝提示（實驗機，按需）**

```bash
sudo zypper in sysstat iotop iftop nethogs vnstat tcpdump nmap traceroute bind-utils hwinfo
```

（套件名稱依實際 repo 可能略有差異；沒有的工具可改寫「為何無法執行／等價指令」。）

## 練習 2. 訊號、優先級與工作控制

| 2-2-4 | 寫出 `pkill -f "python my_script.py"` 適用的情境                    |

### 2-3. `nice` / `renice`

nice 值愈大，排程優先級愈**低**（較禮讓）；負值提高優先級，通常需 root。

```bash

renice 15 -p <PID>
```

| 小題  | 問題                                                     | 作答 |
| ----- | -------------------------------------------------------- | ---- |
| 2-3-1 | 解釋 nice 值與優先級的關係                               |      |
| 2-3-2 | 大量編譯、批次工作通常應提高還是降低 nice？為什麼？      |      |
| 2-3-3 | 寫出對 PID `12345` 將 nice 改為 `15` 的指令              |      |
| 2-3-4 | 為什麼長期把關鍵行程的 nice 調成很大的負值仍可能有風險？ |      |

### 2-4. `jobs` / `fg` / `bg`

完整操作一次並記錄畫面：

```bash
sleep 300
# Ctrl+Z
jobs
bg %1
jobs
fg %1
# 另試：script.sh &   （可用 sleep 120 & 代替）
```

| 操作        | 意義／你觀察到什麼 |
| ----------- | ------------------ |
| `Ctrl+Z`    |                    |
| `jobs`      |                    |
| `bg %N`     |                    |
| `fg %N`     |                    |
| `command &` |                    |

補充思考題：

1. 工作控制綁定的是「目前這個 shell」還是整台機器？關掉終端可能發生什麼？
2. 長時間遠端工作為什麼較建議改用 `screen`／`tmux`？

### 作答／驗收（練習 2）

1. 完成訊號與 nice 概念表。
2. 附上對 `sleep` 測試行程的 PID、訊號與結束驗證。

## 練習 6. Stat：抽樣、對照時段與歷史

這類工具適合抽樣、對照時段、查歷史（如 `sar` 讀 `/var/log/sa/`）。歷史資料依賴 sysstat 是否有在收集。

### 6-1. `vmstat` 快速判讀

```bash
vmstat 1 5
vmstat 2 5
```

| 區塊   | 關鍵欄位                     | 意義（請填） |
| ------ | ---------------------------- | ------------ |
| procs  | `r` / `b`                    |              |
| memory | `swpd` `free` `buff` `cache` |              |
| swap   | `si` / `so`                  |              |
| io     | `bi` / `bo`                  |              |
| system | `in` / `cs`                  |              |
| cpu    | `us` `sy` `id` `wa` `st`     |              |

依輸出做判讀（可寫「本次樣本看不出壓力」）：

| 規則                                       | 你的觀察 |
| ------------------------------------------ | -------- |
| `r` 長期明顯大於 CPU 數 → CPU 壓力         |          |
| `b` 高且 `wa` 高 → 可能 I/O 等待           |          |
| `si`/`so` 持續明顯 → 記憶體不足、在用 swap |          |
| `st` 偏高（VM）→ Host 可能超賣 CPU         |          |

### 6-2. `sar` / `mpstat` / `iostat` / `pidstat` / `vnstat`

寫出指令用途，並至少實作標了「必做」的項目：

| 小題   | 指令範例                                   | 用途（請填）             | 必做                 |
| ------ | ------------------------------------------ | ------------------------ | -------------------- |
| 6-2-1  | `sar -u 1 5`                               | CPU                      | ★                    |
| 6-2-2  | `sar -P ALL 1 5`                           |                          |                      |
| 6-2-3  | `sar -r 1 5`                               |                          |                      |
| 6-2-4  | `sar -b 1 5`                               |                          |                      |
| 6-2-5  | `sar -n DEV 1 5`                           |                          |                      |
| 6-2-6  | `sar -u -f /var/log/sa/sa10`               | 讀當月第 DD 日歷史       | 若 `sa` 目錄存在則做 |
| 6-2-7  | `mpstat -P ALL 1 5`                        | 各核心；與 `sar -P` 互補 | ★                    |
| 6-2-8  | `iostat 2 3`                               |                          |                      |
| 6-2-9  | `iostat -x 2 3`                            | await、util 等           | ★                    |
| 6-2-10 | `pidstat -u 1 5`                           |                          |                      |
| 6-2-11 | `pidstat -p <PID> -u 1 5`                  | 指定 PID                 | ★                    |

3. 若 `/var/log/sa/` 沒有資料，代表什麼？下一步應檢查哪個服務／套件？

### 6-3. 監控策略

## 練習 7. 網路排查（一）：連通、介面、監聽、DNS

建議由外而內、由簡而繁：先確認 L3 可達，再查本機介面與監聽埠，再查 DNS、防火牆與封包內容。

### 7-1. `ping` / `traceroute`

| 現象                         | 可能意義（請填） |
| ---------------------------- | ---------------- |
| Destination Host Unreachable |                  |
| Network is unreachable       |                  |
| Request timed out            |                  |
| 高 RTT／丟包                 |                  |
| traceroute 在某跳停止        |                  |

建議步驟（請實際執行並記錄；目標可改為閘道、同網段主機、`8.8.8.8`、課程允許的網域）：

1. `ping` 閘道 → 同網段主機 → 外部 IP → 網域名稱

## 練習 9. 綜合排查情境

不必真的把系統弄壞；寫出**檢查順序、指令與判讀**即可。能在實驗機模擬者加分。

### 9-1. 網站開不了

使用者回報「網頁打不開」。請依本章總結步驟寫出清單，並為每步填一個代表指令：

| 順序 | 層面                   | 代表指令 | 若失敗，可能原因 |
| ---- | ---------------------- | -------- | ---------------- |
| 1    | 連通（閘道／IP／域名） |          |                  |
| 2    | 路徑                   |          |                  |
| 3    | 本機介面與路由         |          |                  |
| 4    | 服務是否在聽           |          |                  |
| 5    | 名稱解析               |          |                  |
| 6    | 政策層（firewall）     |          |                  |
| 7    | 封包層                 |          |                  |
| 8    | 對端視角（授權下）     |          |                  |

### 9-2. 系統變慢

CPU、磁碟、記憶體、網路都可能。請設計一條「先大局、再鑽入」的路徑。

| 步驟 | 工具                | 你想排除／確認什麼 |
| ---- | ------------------- | ------------------ |
| 1    | `vmstat` 或 `top`   |                    |
| 2    | （依上一步結果）    |                    |
| 3    | （再往 PID／裝置）  |                    |
| 4    | （需要歷史時）`sar` |                    |

情境提示（任選一題深入作答）：

1. `r` 很高、`wa` 很低 → 較像哪類瓶頸？接下來 `mpstat`／`pidstat` 看什麼？
2. `b` 與 `wa` 都高 → 為什麼接著看 `iotop`／`iostat -x`？
3. `si`/`so` 持續有值 → 為什麼要回頭看 `free -h` 的 available？
4. VM 上 `st` 偏高 → 問題可能在 Guest 還是 Host？

### 9-3. 埠被占用、服務起不來

某個服務啟動失敗，日誌出現 `Address already in use`。

請寫出：

1. 用 `ss -tunlpa` 與 `lsof -i :PORT` 找出占用者。
2. 如何確認是該殺舊行程、改埠，還是不該動手（系統 sshd 等）。
3. 若誤用 `kill -9` 可能有什麼副作用？

### 9-4. 刪了大檔但 `df` 空間沒回來

請說明：

1. 為什麼刪除後空間可能仍被占用？
2. 會用 `lsof` 的哪類查法找仍開啟該檔的行程？
3. 處理原則（重載服務／結束行程，而不是再刪一次）。

### 作答／驗收（練習 9）

1. 9-1 必須寫出完整分層清單。
2. 9-2～9-4 擇一深入即可；全做為加分。
3. 強調：先辨識（`ps`／`pgrep`／`pstree`），再動作（`kill`／`renice`），最後用 `lsof` 看握著什麼；網路則先分層、不要盲目重啟。
